## Native conversation integration boundary

The installed [multi-user contract](https://docs.openclaw.ai/concepts/multi-user) records creator and participants only when an authenticated Gateway profile or channel sender supplies identity. A shared token does not distinguish humans. The installed [Gateway integration contract](https://docs.openclaw.ai/gateway/external-apps) recommends WebSocket RPC/events and `sessions.*` for external apps. Its `gateway.roles` policy can restrict authenticated profiles to specified agents and session access, but the current Gateway has no identity-bearing local reverse proxy or Tailscale identity and no collaborator role. OpenClaw also documents that operator write scope includes Gateway-wide actions and that same-agent ownership is not isolation.

The [disposable native probe](NATIVE_GATEWAY_PROBE.md) confirmed that a role allowlist rejects creating a `main` session but does not conceal an existing private `main` session under the `sessions.others="write"` policy needed for the shared owner-created session. The continuation chose a separate Gateway containing only shared material and a method-filtered host relay. The host authenticates a device, maps a verified Gateway suggestion profile/session/ID to an idempotent project input, and retains grant/dispatch authority. The direct collaborator route to the original Gateway remains unavailable. A second real person must join the **same** session and receive a reply before multiplayer acceptance can be called complete. No new external channel, tunnel, or deployment was enabled here.

Installed `2026.9.4` session roles leave no safe direct-connection setting for the original single Gateway: `none` hides foreign sessions by default, `view` cannot mutate them, and `suggest` allows only suggestions. Explicit membership can elevate only view/suggest for one session. `write` permits collaboration but the fixture proved that it also reveals owner-private sessions. The staged separate Gateway/relay still needs a loaded host binary, a second authenticated human, an actual reply route, and a verifiable provider-request accounting contract for a new live revision demonstration. The historical three-artifact pilot remains available for review meanwhile.
