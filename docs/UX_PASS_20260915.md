The UX pass shipped as `portable-ux-pass-20260915-b` at
http://localhost:5179/. The owner study, existing records and login were
preserved through a verified backup and package change. The mood journal then

## Fixed during the pass

- Closing an app returns to the conversation once Chat has been opened beside
  it. Opening and closing directly from the shelf still returns to the shelf.
  The return destination survives app URL reloads. Chat drafts survive pane
  toggles, and keyboard focus returns to the composer on closing into Chat.
- Hidden Chat follows its latest messages when revealed. Scrolling up to read
  prevents background updates from pulling the transcript to the bottom.
- Idle task results no longer display a misleading zero. The result panel closes
  on outside click or Escape, returns keyboard focus, and anchors to its button.
- Shelf edits, deletion and restoration display confirmation. Deletion offers
  immediate Undo; Trash still offers Restore with the original records.
- Generated apps have one scrollbar while Data & history is closed. Their
  scrollbars use the compact browser style. Recovery tools remain available.
- Native forms now receive validation and submit events so Enter/Add/Save
  handlers can persist through the existing bridge. `form-action 'none'` still
  blocks host-directed and external form submissions. Same-origin access,
  external fetch, popups and top navigation remain unavailable.
- Generated pages receive theme information and `--on-accent`. The model prompt
  requires paired foreground/background contrast, focus states and save/error
  feedback. The existing mood page was checked in dark and paper themes.
- The Luna development bridge carries page HTML/CSS/JavaScript in a structured
  page object, then serializes the final tool arguments. This removes the extra
  JSON escaping layer that rejected the first live edit attempt. Invalid
  proposals still fail without changing an app or automatically retrying.

## Evidence and practical limits

Hands-on CUA testing in a disposable study created a new checklist with Luna
High, exercised Enter/Add, checkboxes, deletion, reload, and a real layout edit.
The edit added working All/Active/Completed filters, retained the completed
record and preserved an unfinished input while changing filters. A copy of the
owner's mood page passed manual form add/edit and dark/paper visual checks.
To-do add/complete/archive/restore, idea creation, local search navigation and
Feed tab navigation were also exercised. Feed fetching was not repeated.

Three live Luna High requests used **63,009 provider-reported tokens** including
the rejected edit: 18,667 create, 22,203 rejected edit, 22,139 successful retry.
These were deliberate, bounded manual QA calls, not routine regression calls.
The failed HTTP response did not report usage to the study, so its conservative
reservation remained there; the provider receipt supplies that missing count.
The fictional study was removed after compact receipts were retained in
`artifacts/ux-pass-20260915/manual-ux.json`. No web-search or GPU calls were made.

Focused checks passed: four `ArtifactApiTests`, seven bridge/protocol tests,
the generated-page browser workflow, the background-chat browser workflow and
the new native-form/navigation/CRUD/theme/mobile browser workflow. The final
package passed that last workflow in `artifacts/ux-final-20260915`. It verifies
both local form persistence and zero outgoing form submissions, including
recovery when Chromium replaces a blocked frame with an error document.
Phone-width checks are browser layout checks, not physical-phone qualification.

The final package differs from candidate A only in the frame scrollbar styles
and revised test expectations for Chromium's blocked-navigation behavior.
Earlier valid backend/generated/background evidence was reused. Runtime asset
hashes, source hashes, login/backup preservation and package staging cleanup are
recorded in `artifacts/ux-pass-20260915/activation/live-verification.json`.

Generated code can still contain application-specific defects. One successful
creation and edit is evidence for this path, not a guarantee for every app.
Keep model-designed layouts, but treat reliable save/error feedback and recovery
controls as product requirements. Additional broad benchmarks, Mac execution
and physical-phone setup remain deferred.
